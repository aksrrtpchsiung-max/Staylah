# Original module → refactored code mapping table

This is the only manual module mapping list for the entire project. The numbers are kept as team communication shorthand, while the new directories use business names.

**To modify business implementations, see the last column.** After the real A→B→C pipeline was fully working, the old entry points, compatibility files, teaching project, and unused historical tools were deleted. The old paths in the table are only for recalling the original division of work; for imports and execution, use the new paths. The original startup commands for the web page and the overall session remain unchanged.

PropertyGuru retains the three adapters used by the formal application: search, detail, and contract-listing.

## Quickly locate your B

In daily communication, you can still say "modify 2's scheduling" or "check 3c's amenities." When actually making changes, go to `property_agent/search/`:
1 corresponds to `planning`, 2 corresponds to `execution/supervisor`, 3a/3b/3c/3d correspond to the four named files in `capabilities`, and 4/5 correspond to the two files in `aggregation`. Shared requirement rules are located separately in `property_agent/domain/`.

`guru_search` is still the website tool used by 3a. The integration methods for LangGraph, PropertyGuru, OneMap, or OSM have not been changed.
